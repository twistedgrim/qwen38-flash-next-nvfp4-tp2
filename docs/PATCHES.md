# Patch provenance

## SM121 Qwen sparse-attention resolver

The pinned SGLang image contains a Qwen sparse-attention resolver that enables
the FlashInfer TRT-LLM sparse decode path only when `is_sm100_supported()` is
true. GB10 reports SM121, so the resolver falls through to the FA4-CuTe path.
For this model/head shape, that fallback failed during warmup with:

```text
expects `coord` and shape of view are weakly congruent
```

The recipe overlays one Python module and changes only the architecture gate:

```diff
- from sglang.srt.utils import is_sm100_supported
+ from sglang.srt.utils import is_sm100_supported, is_sm120_supported

- if not is_sm100_supported():
+ if not (is_sm100_supported() or is_sm120_supported()):
    return None
```

The resolver's existing runtime capability/head-shape checks remain intact.
The patch is generated by `scripts/prepare-qsa-sm121-patch.sh` and mounted
read-only over the original module. The image itself is never modified.

Safety controls:

- immutable image digest;
- expected source SHA-256
  `c959835d05d0f395ad7eae4330cf264af9f6f7c1bff3d45a39bb953d2536f5f2`;
- exact single-match replacement;
- Python compilation before use;
- generated output excluded from Git.

SGLang commit `7c66045d71f067c1c5da2b85baad3c47d9a19cb7` merged the equivalent SM121
resolver support after the pinned image was built. Remove the overlay only
after a refreshed immutable ARM64 image is available and passes the full
recipe validation suite.

## M-RoPE patches

This recipe uses `--language-only`; it does not apply third-party M-RoPE/vision
kernel patches. If multimodal input is enabled later, image-specific rotary
kernel behavior must be validated independently rather than bundled into this
text-serving patch.
